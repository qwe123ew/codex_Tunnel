# 常见问题与排查

[返回首页](../README.md) · [新电脑逐步说明](../VSCode-快速配置.md)

先看失败发生在哪一步：**读取服务器 → 本机代理检测 → SSH 认证 → 远端检测 → VS Code 配置 → Codex 登录与调用**。前一步成功不能证明后一步也成功。

## 没有发现服务器，或者只有名称没有地址

1. 点击 **刷新**，确认选择的是当前电脑上能正常连接的条目；有 VS Code 来源时优先选用它。
2. 程序自动读取用户 `.ssh/config`，以及 VS Code / Insiders 默认用户设置中指定的 `remote.SSH.configFile` 和 `remote.SSH.path`。便携版、自定义用户数据目录或其他终端软件的连接不会全部自动发现，可点击 **选择文件**。
3. 新电脑没有任何资料时，点击 **启动连接** 或 **添加服务器**，根据管理员提供的地址、用户名、SSH 端口和跳板路线填写。
4. 已有别名却解析失败时，查看日志中的实际 SSH 客户端与原因。不要删除原本能使用的 SSH 配置。

GUI 支持原生 SSH 认证选项、多密钥、`ProxyJump` 和 `ProxyCommand`。配置中的 `Match exec` 可能在解析时执行命令，程序不自动接受它；网络共享配置路径和超出大小/深度上限的配置也会被拒绝。无法简化的特殊认证流程需要按原连接方式处理，手工填写地址不能代替认证命令。

软件保存的服务器列表与 VS Code 的列表分开。若只在软件里添加了服务器，还需在 VS Code 使用 **Remote-SSH: Add New SSH Host...** 建立入口，详见[配置步骤](../VSCode-快速配置.md)。

## 没有检测到本机代理

- 先启动代理软件，并启用 HTTP / Mixed 监听。只启用 SOCKS、TUN 或 PAC 不代表存在本工具可用的 HTTP 入口。
- 在代理软件中查看实际端口，在 **高级设置 → 本机代理端口** 填写后重试。无需启用局域网访问。
- 自动发现只检查本机回环地址，候选数和总检测时间有上限；未知软件的特殊端口可能需要手动填写。
- 两次目标 HTTPS 检测都通过才会接受入口。只出现 `200 Connection established`、TLS 错误、超时或 HTTP `403` 都不算通过。

可在 Windows PowerShell 手动核对，把 `7890` 替换为代理软件实际的 HTTP / Mixed 端口：

```powershell
curl.exe --proxy http://127.0.0.1:7890 --noproxy localhost --connect-timeout 5 --max-time 20 -I https://api.openai.com/v1/models
```

HTTP `401` 表示这次未认证请求到达服务。若出现证书错误，检查电脑时间、证书链和代理状态；不要用关闭 TLS 验证的方法掩盖问题。

## SSH 密码窗口没反应或连接失败

输入密码时通常不会显示字符，输入完成按回车即可。需要验证码的连接，按窗口中的提示操作；软件不保存或代填密码。

- **Permission denied**：核对失败的是跳板机还是目标服务器，再检查对应用户名、密钥和认证权限。
- **Connection timed out / refused**：检查 SSH 地址、端口、网络/VPN 和跳板机是否可达。
- **主机指纹发生变化**：通过管理员或可信渠道核对服务器变更原因，按正常 SSH 流程处理，不应关闭主机验证。
- **认证窗口立即关闭**：查看软件日志；使用与 VS Code 相同的 SSH 配置和客户端重试。

软件只管理自己启动的进程。停止隧道不会停止其他正常的 VS Code / SSH 会话；关闭隧道认证窗口则会结束本次隧道。

## 提示远端端口已占用或不允许转发

同一服务器的同一个端口不能同时被两条独立隧道绑定。

1. 如果旧电脑仍开着本工具，先在那里停止自己的隧道。
2. 或在 **高级设置** 改为另一未占用的远端端口，例如 `11083`，重新启动并再次点击 **一键配置 VS Code**。
3. 若服务器禁止 TCP 反向转发，需要管理员调整相应 SSH 策略；更换软件不能绕过该限制。

若提示监听范围超出回环地址，程序会关闭本次隧道。请管理员检查 SSH 服务的 `GatewayPorts` 等设置，确保代理不会公开监听在外网地址。

## 本机代理通过，但远端未就绪

本机通过只验证 Windows 到目标服务的路径。远端检测还包含 SSH 转发和服务器工具是否可用。

在服务器终端执行以下命令，替换为软件显示的远端端口：

```bash
curl --proxy http://127.0.0.1:11082 --noproxy '' \
  --connect-timeout 5 --max-time 20 -I https://api.openai.com/v1/models
```

- 找不到 `curl`：远端无法自动验证，请按服务器允许的方式安装或联系管理员。
- `Connection refused`：检查隧道仍在运行、服务器一致、远端端口一致。
- TLS 错误或超时：检查 Windows 代理节点与网络；CONNECT 响应不等于最终 HTTPS 成功。
- 心跳超时：状态会转为未验证；检查电脑休眠、断网、代理退出或 SSH 断线。

远端默认每 60 秒检查一次。网络恢复后可以重新启动隧道；程序不会自动循环提交认证信息。

## “一键配置 VS Code”失败

| 提示或现象 | 处理方式 |
|---|---|
| 未找到 VS Code Server 或 Node | 先用 VS Code Remote - SSH 成功连接同一服务器账号，保持远程窗口打开再重试 |
| 自定义安装位置未被识别 | 保持目标 VS Code Server 运行；程序可从相应远端环境和当前账号的服务进程识别部分自定义位置，不会猜测任意目录 |
| 设置语法错误 | 在 VS Code 打开 **Preferences: Open Remote Settings (JSON)**，修正语法后重试；程序不会以空文件覆盖 |
| 权限不足或不安全的文件链接 | 检查目标设置文件的归属、权限和链接结构；不要给任意用户开放写权限 |
| 设置正在被修改 | 等待其他编辑或配置操作结束，再重试 |
| 配置超时或取消 | 认证最长等待 5 分钟；再次点击配置可检查并完成。远端可能已写入但结果未返回，取消不等于撤销 |
| 提示部分设置无法恢复 | 在远端核对设置与保留的备份，确认后再重试 |

配置使用独立 SSH 会话，可能要求第二次认证；不需要重复绑定代理端口，也不会停止已经运行的隧道。

## 如何恢复配置前的远端设置

如果原设置文件存在且确实需要更新，程序会在同目录保存完整备份，名称类似：

```text
settings.json.codex-tunnel-backup-时间-随机编号
```

标准稳定版通常位于 `~/.vscode-server/data/Machine/`，Insiders 通常位于 `~/.vscode-server-insiders/data/Machine/`；自定义安装和用户数据目录以实际路径为准。

先停止其他设置编辑，比较备份和当前 `settings.json`，确认要恢复的版本后再替换。恢复整个备份也会撤销备份之后对该文件的其他修改，因此不要未经比较直接覆盖。替换后在 VS Code 执行 **Developer: Reload Window**。

若配置前没有设置文件，则没有旧文件备份；可在远程设置中移除本工具新增的两个代理键，并保留其他内容。停止隧道不会自动撤销已保存的远程代理设置。

## 配置成功，Codex 仍然无法使用

依次确认：

1. 软件仍显示 **远端代理已就绪**，当前电脑没有休眠，代理仍开启。
2. VS Code 连接的是同一服务器和同一账号。
3. 软件端口与远程 `http.proxy` 端口一致，修改服务器或端口后已重新配置。
4. 已在 VS Code 远程窗口执行 **Developer: Reload Window**。
5. 官方 Codex 扩展安装在 **SSH: 当前服务器**，发布者为 OpenAI。
6. 检查工作区等其他设置范围是否覆盖代理；本工具不会自动修改项目设置。
7. 按扩展提示完成登录，并检查账号与模型使用权限。

网络检测、设置保存、账号登录和实际模型调用是不同结果。`api.openai.com` 可达也不能证明所有登录域名均可达。

扩展下载失败时，可从官方扩展来源获取匹配远端 **Linux 架构** 的 VSIX，在远程窗口执行 **Extensions: Install from VSIX...**；不要复制 Windows 版扩展目录。若浏览器登录回调明确指向 `localhost:1455`，可在 VS Code“端口”面板转发远端 `1455`，确认本地也映射到 `1455`，再重试该登录流程。

## 换电脑、删除 ZIP 或卸载

- **删除 ZIP**：不影响 EXE；程序内置运行脚本。
- **换电脑**：复制 EXE 即可，然后读取新电脑的 SSH 配置或重新添加服务器。不要把个人私钥或登录文件放入共享压缩包。
- **同一账号多台电脑使用**：远程代理设置共享。接管相同端口前，先停止旧电脑自己的隧道；不同服务器可以各自使用 `11082`。
- **卸载**：先停止并关闭程序，再删除 EXE。软件保存的连接资料位于 `%LOCALAPPDATA%\CodexProxyTunnel`，是否保留由你决定；远程代理设置需按上面的恢复步骤单独处理。

## 报告问题时提供什么

请在 [GitHub Issues](https://github.com/qwe123ew/codex_Tunnel/issues) 提供软件版本、Windows / VS Code 版本、失败步骤、界面错误和相关脱敏日志。说明相同服务器能否用 VS Code Remote - SSH 正常连接。

把真实地址、用户名及个人路径替换为占位符，保留错误码、配置项名称和端口关系。不要上传密码、验证码、API Key、访问令牌、私钥或整个个人配置目录。
