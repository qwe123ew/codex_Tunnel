# Codex Tunnel GUI v2.4.0 设计与实施

目标：以原生 Windows 窗口完成 SSH 主机选择、本机代理检测、连接启动、状态查看和停止操作。认证仍在独立 SSH 窗口中完成。GUI 不读取、存储或代填密码。

## 视觉方案

本次依据用户明确选择的“灰白＋浅蓝”，重新设计配色和按钮。视觉参考由内置 imagegen 生成，保存在 `assets/design-concept-v2.1.png`；原 v2.0 设计稿保留供历史对照。实现采用原生 WPF 控件，设计参考图没有作为整张图片嵌入程序。

- 窗口：默认 1100 × 780，最小 940 × 720，支持缩放和高 DPI。内容采用自适应 Grid；高度不足时整体内容可滚动，日志另有独立滚动。
- 背景 `#F5F7FA`；面板 `#FFFFFF`；次级底色 `#F8FAFC`；边线 `#E3E8EF`。使用细分隔线与留白，不添加渐变、厚重阴影或大面积色块。
- 主要文字 `#283444`；辅助文字 `#64748B`；浅蓝强调底 `#DBEAFE`；按钮文字 `#285B93`。成功 `#327A64`、注意 `#956425`、错误 `#B65050` 只表达状态，不作为大面积背景。
- 字体：Segoe UI、Microsoft YaHei UI；日志和地址优先 Consolas。面板圆角 10 px，按钮圆角 8 px；标题、字段和操作遵循统一对齐与间距。
- 顶部：小型线条图标、单一标题“Codex Tunnel”、短说明和中性状态标签。去掉重复的大写品牌与装饰标签。
- 主体：左侧服务器卡片占约 56.5%，右侧本机代理与隧道状态卡片占约 43.5%；底部共享连接日志。
- 高级端口设置默认收起，本机端口留空自动检测，远端端口默认 11082。具体内容可展开编辑。

## 按钮与控件

- 主操作“启动连接”：约 152 × 42 px，浅蓝底、深蓝文字，线条播放图标；停止为较窄的白底细描边按钮与方形图标。
- 检测代理：白底描边次操作；刷新、选择文件、复制、清空和帮助为轻量辅助按钮。图标使用原生矢量路径，文字与图标分开绑定，按钮显示“正在检测”等动态文字时不会丢失图标。
- 主按钮常态底 `#DBEAFE`、悬停 `#CFE3FA`、按下 `#BBD6F5`，描边 `#B9D3F0`。键盘焦点为 `#518CCB` 的清晰轮廓，禁用状态降低对比且不能触发操作。
- 下拉框、输入框、选择项、文本选区、滚动条与展开箭头统一使用浅色方案。日志使用浅灰底与深灰文字，支持选择复制。
- 每种按钮的视觉样式与控制状态分别验证；离屏预览展示控件布局，不等同于手动鼠标与键盘验收。

## 软件图标

- 图标为浅蓝圆角底上的两个相扣链环，以深蓝与中蓝区分前后，表达 SSH 隧道连接。使用简洁轮廓与较粗笔画，缩小后仍保留两个链环的形状。
- 原始图标由内置 imagegen 生成，保存在 `assets/app-icon-source.png`，保留外部透明区域。
- `Build-Icon.ps1` 使用现有 .NET 图像编码功能导出 ICO 格式，包含 16、20、24、32、40、48、64、128、256 px 共九种尺寸，避免只给大图导致小尺寸模糊。
- `Build-Gui.ps1` 将图标写入 EXE 的 Windows 图标资源，并附带独立品牌资源供 WPF 窗口与页头使用。九个运行资源保持独立。

## 添加服务器与来源识别

- 沿用灰白背景、白色表单、浅蓝主按钮和线条图标；新的 imagegen 对话框参考保存在 `assets/add-server-concept-v2.2.png`。
- 服务器卡片提供“添加服务器”，已保存条目可编辑。下拉框标注软件保存、本机 SSH 或 VS Code 等来源；空列表仍提供明确的添加入口。
- 对话框先填写名称和目标服务器参数，再按顺序添加跳板机。每个端点都有独立用户名、端口和可选密钥路径；跳板行带编号与删除按钮，最多四行。
- 表单内容可滚动，保存与取消位于固定操作区。字段错误在表单内显示，保存期间锁定重复提交；失败后保留输入。
- 保存成功后自动选择新条目。软件自己的服务器文件和外部 SSH 配置保持分离；自动读取失败只影响相应来源。
- v2.3 原生 SSH 模式保留已有认证和跳板设置；日志显示实际采用的 SSH 客户端，解析失败显示固定的具体原因。连接帮助改为分步 VS Code 设置指南，沿用现有浅色控件，底部提供“复制远程设置 JSON”，使用当前远端端口。

## v2.4 一键配置与首次使用

- 布局参考通过内置 imagegen 生成并保存为 `assets/vscode-setup-concept-v2.4.png`。提示词：灰白浅蓝原生 Windows Codex Tunnel；左侧服务器、右侧代理与状态、底部日志；增加“一键配置 VS Code”与首次添加服务器的“保存并连接”引导，保持留白和细描边。生成图是参考，真实软件使用 WPF 控件，实际布局与文字以控件预览为准。
- 复用背景 `#F5F7FA`、白卡片、文字 `#283444`、辅助文字 `#64748B`、按钮浅蓝 `#DBEAFE` 和蓝字 `#285B93`。在连接操作区放置“启动连接”“停止”“一键配置 VS Code”，窄窗口允许换行；配置说明与取消按钮紧随其后，避免增加大面积面板。
- 无服务器时“启动连接”保持可用，打开包含地址/账号/端口/跳板说明的引导。主按钮按来源显示“保存并连接”或“保存并配置”；只有保存、重新选中、解析全部成功后继续，取消不启动。普通“添加服务器”仍仅保存。
- 配置进度、成功、失败和取消均在独立区域显示。配置期间锁定服务器和端口；正在运行的隧道仍可停止。配置成功提示端口与“重新加载远程 VS Code”，不将设置成功表示为联网或登录成功。
- 远端配置通过独立 SSH 认证窗口执行，不重新绑定代理端口。后台使用单独的进程所有权和 5 分钟超时；关闭软件会结束本软件的隧道及配置进程。

## 状态与行为

- 初始状态为“未连接 / 等待连接”，颜色中性。已有条目须成功解析后才可启动；空列表允许点击启动进入引导。未运行时禁止停止。
- 选择主机后异步解析并显示地址、用户、SSH 端口和按顺序保留的跳板路径。繁忙期间锁定主机选择。
- 启动后锁定配置，提示用户在 SSH 窗口中完成认证。只在收到远端 `ready` 状态时显示绿色“已就绪”。
- `detecting`、`connecting`、`degraded`、`unverified`、`error`、`stopped` 均有明确中文状态；未知值回退至中性状态。
- 本机代理 HTTP 响应单独展示。代理可达、远端验证和账号认证是不同结果。
- 状态序号单调递增，界面忽略迟到的旧消息；`bind-warning` 只追加提示日志，保留当前健康状态。本机 HTTP 使用独立的 `ProxyHttpStatus`，不会被远端 HTTP 结果覆盖。
- 隧道卡片显示最近一次收到远端成功验证的本机时间；后续状态变化保留该记录，并在每次重新启动连接时清除。该时间是最近验证记录，不表示之后的持续健康保证。
- 复制日志使用系统剪贴板；清空只清理当前界面；帮助提供实际可执行的 SSH 信息查询命令。
- 后台事件通过 Dispatcher 更新界面；配置解析、代理检测、停止操作异步执行。关闭窗口调用后端 Dispose，只处理本次连接。

## 实现与验证

1. `GuiApp.cs`、`ServerEditorWindow.cs`：主界面、添加和编辑表单、状态映射、异步事件、字段校验、预览和控制状态自检。
2. `TunnelBackend.cs`、`ServerCatalog.cs`、`Gui-Api.ps1`：由后端负责独立服务器存储、自动发现配置、运行时提取、PowerShell 调用、进程所有权与状态协议。
3. `Build-Gui.ps1`：使用 Windows 自带 .NET Framework 编译器构建 WPF winexe；资源为九项运行文件加一个品牌图标的明确白名单，不嵌入本机配置或日志。新增远端 JSONC 编辑器及其 shell 引导脚本。
4. `app.manifest`：普通用户权限与 PerMonitorV2 DPI 声明。
5. `--ui-self-test <绝对 JSON 路径>`：无网络、无真实用户配置，检查初始引导入口、各状态颜色、配置锁定、取消和端口验证。
6. `--render-preview <绝对 PNG 路径> [窗口宽度 窗口高度] [default|advanced|connected|dropdown|buttons|empty|add-server|add-jumps|onboarding|vscode-config|vscode-configuring]`：将真实 WPF 内容树装入离屏画布，使用明确的合成示例生成预览；不建立网络连接。支持高级设置、连接状态、下拉列表、空列表、添加表单、多跳板表单、首次使用、远端配置结果和按钮交互状态。按钮展示在测试模式下注入输入状态，不是手动操作验收。默认窗口尺寸 1100 × 780，可用 `940 720` 检查最小窗口尺寸；主界面图像只包含内容区，高度扣除 40 px 系统标题栏预留。

构建默认输出 `dist/gui/CodexTunnel.exe`。`-OutputDirectory` 可指定新的目录，避免覆盖被安全软件或正在运行的进程占用的旧产物。编译成功、自检成功、预览视觉检查与真实 SSH 登录验证是分别记录的验证层次。
